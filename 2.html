Variablen speichern einen Wert eines (eingebauten) Datentypen.

Sie können aber auch noch vieles mehr speichern: die Referenz auf ein Objekt (Instanz einer benutzerdefinierten Klasse), eine Funktion, ein Modul, None, ...

In Python kann man einfach Variablen direkt Werte eines beliebigen Typs zuweisen. Man darf der gleichen Variable später auch einen Wert eines anderen Typs zuweisen. Dies nennt man dynamische Typisierung.

Konstanten

In anderen Programmiersprachen gibt es Konstanten, also Variablen, die nach ihrer Initialisierung nicht mehr verändert werden können.

In Python gibt es keine Konstanten!

ANZAHL_SPIELER = 3; ← den Wert sollte man nicht mehr verändern.

Was passiert, wenn man jetzt trotzdem ANZAHL_SPIELER = 3 macht?

  • Kommt ein Fehler
  • Der Wert bleibt trotzdem 2
  • Der Wert wird auf 3 geändert
  • Der Wert wird auf None gesetzt

https://fraage.de

Python kennt nur Variablen. Deren Wert ist also variabel, er lässt sich beliebig verändern. Manchmal hat man aber auch mit Konstanten zu tun, also quasi eine Variable, deren Wert, nachdem er einmal gesetzt ist, sich nicht mehr ändert. Das kann man zwar in Python nicht erzwingen, aber es hat sich als Konvention etabliert, dass man den Namen einer Konstante einfach komplett in Großbuchstaben schreibt. Daran sieht man, dass es sich um eine Konstante handelt. Normale Variablennamen schreibt man dagegen klein. Das ist guter Code-Stil.

Code-Einrückungen

10 3.4

Den Code einzurücken ist in Python wichtiger als in jeder anderen Programmiersprache! Einrückungen sind Teil der Syntax!

  • Python verwendet Einrückungen, um Blöcke zu definieren.
  • Tab oder beliebig viele Leerzeichen verwenden
  • Empfehlung: 4 Leerzeichen, keine Tabs
  • Blöcke bestimmen in Python nicht den Gültigkeitsbereich von Variablen. Variablen sind im gesamten Funktions- oder Modulbereich gültig, in dem sie definiert sind.

if / elif / else

10 3.4

Folgt nur ein Kommando, darf man das direkt in der gleichen Zeile direkt nach dem Doppelpunkt hinschreiben:

Hinter dem Doppelpunkt beginnt man eine neue Zeile, die eine Stufe weiter eingerückt ist, als die vorherige Zeile. Dort beginnt dann der Code-Block, also beim if das, was gemacht wird, wenn die Bedingung erfüllt ist. Der Code-Block ist dort beendet, wo die Einrückung wieder auf dem Level zurück links ist, wie das if selbst. Das untere Beispiel - der Einzeiler - ist zwar gültig. Aber es ist schönerer Stil, wenn man auch bei solchen Einzelnern nach dem Doppelpunkt einen Zeilenumbruch macht und das Statement eingerückt in die nächste Zeile schreibt. Das macht den Code leserlicher, erleichtert die Wartung und es ist erweiterbarer. Wer weiß, ob man in Zukunft noch weitere Kommandos hinzufügen will.

pass

pass macht gar nichts.
Man braucht es, wenn man in einem Code-Block nichts ausführen will.

Ohne das pass käme ein Fehler, weil nach if usw. ein Codeblock mit mindestens einem Statement erwartet wird.

Lokale und globale Variablen

Variablen, die innerhalb einer Funktion definiert werden, sind nur innerhalb der Funktion sichtbar. Sie heißen lokale Variablen.

if __name__ == "__main__":

Es ist guter Programmierstil, wenn man die Haupt-Programmlogik in eine Funktion main() schreibt und diese am Ende des Scriptes nach Überprüfung von
if __name__ == "__main__": aufruft:

  • (+) Modularität: Das Script kann in anderen Python-Scripten importiert werden. In dem Fall wird main() nicht aufgerufen.
  • (+) Wiederverwendbarkeit: Funktionen aus dem Script lassen sich in anderen Scripten wiederverwenden.
  • (+) Testbarkeit: Ein separates Script, welches einen Unit-Test macht, kann Funktionen aus diesem Script aufrufen und prüfen, ob sie das korrekte tun.
  • (+) Lesbarkeit: Man sieht direkt, was beim Aufruf des Scripts gemacht wird.

Komplexe Datenstrukturen

3.10

Mit diesen Datenstrukturen lässt sich eine Sammlung vieler Werte speichern:

  • list (Liste): ListeSortiert, Zugriff über Positions-Index (0, 1, 2, ...)
  • tuple (Tupel): simple unveränderliche Liste
  • set (Menge): Ungeordnet, keine Duplikate
  • dict (Dictionary): Menge von Schlüssel-Wert-Paaren;
    Schlüssel-basierter Zugriff
Listen haben eine Ordnung, d. h. es gibt ein nulltes Element, ein erstes und so weiter. In Listen darf ein Element auch doppelt vorkommen. Mengen (Sets) sind dagegen ungeordnet und frei von Duplikaten. Fügt man ein Element in eine Menge ein, welches schon vorhanden ist, passiert nichts.
Dictionaries heißen in anderen Programmiersprachen Maps oder assoziative Arrays. Sie sind eine ungeordnete Menge von Schlüssel-Wert-Paaren. Man greift auf einen Wert zu, indem man den Schlüssel angibt.

Eine Liste wird erzeugt mit eckigen Klammern ([] ist eine leere Liste), in der ihre Elemente Komma-getrennt aufgezählt werden. Über eckige Klammern greift man lesend und überschreibend auf die einzelnen Elemente zu. len liefert die Anzahl der Elemente.
